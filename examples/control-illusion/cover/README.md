## 4 两条实测发现（都留档在 `assets/assets.json`）

1. **正片 S4 的对比柱有几何 bug（不是本轮改的，v7 成片就是这么出的）**：
   `bar(x, yBottom, w, h)` 把柱体 `top` 设成了 `ry(0.885)=956`（那是**柱底**），没有减掉柱高，
   于是 475px 高的金柱有 88% 落在画外，S4 屏里只剩 `y956–1080` 一块 124px 的柱头，
   而 118px 的灰柱恰好完整 —— 两根柱子在成片里看起来一样高，4 倍差距表达不出来。
   音效事件名是「S4 对比柱从底部生长」，说明本意是「柱底锚在 y=956、向上生长」。
   封面按**本意几何**（柱底 = baseline）重渲了柱体，材质仍是正片那一份 CSS，没有重画。
   → 建议在 **v8** 把 `bar()` 里的 `top` 改成 `yBottom - h`（一行），S4 屏的 4 倍差距就能立起来。
2. **本机 headless 下 canvas `fillText` 画中文会回退成缺字方框**（DOM 渲染正常，canvas 不行）。
   所以封面里的「行盒 → 墨迹中心」补偿没有走 canvas 估算，而是**从成品图实测标定**：
   标题 `inkDx=+6`、副标题 `+2`、`4×` `inkDx=+39 / inkDy=-33`，三条都写回版面表，
   重渲后三者的墨迹中心分别是 960 / 960 / 960.5。

## 6 与方案C 原文的 3 处偏差（都有理由）

1. **右柱填充**：方案写「半透深灰 #333338 填充」。成片的 `.vbar-gray` 是 `rgba(245,241,232,.34→.08)` 的暖浅灰渐变（在深底上就是一根暗灰柱）。为了守住「不重新绘制图形、直接用成片资产」，封面沿用了成片填充，只把描边改成方案指定的 `#B4B4B4`。
2. **主标题字体**：方案要「金色粗无衬线」，就用了无衬线粗体（Microsoft YaHei 系）+ 成片的金属材质；正片正文/角标仍是衬线，保持同源。
3. **540×960 那张**：16:9 的封面放进 9:16 槽位是等比适应（上下留炭黑），所以它只用来校验「缩下去还认不认得出」，真正的清晰度数值取自 540×304。

node cover-check.mjs --json "..\qa\v2\v7\cover\封面校验-实测.json"   # 8 条《最终校验项》逐条给数
node imgscan.mjs "..\qa\v2\v7\cover\cover-C-A-1920x1080.png" 112   # 终端里把成品打成字符图，直接「看」版面

# vibe-knowledge-video-skill

> 复刻「Vibe 知识大赏」风格：**120–150s · 16:9 · 无人类旁白** 的 HTML 科普短视频 —— 全链路制作规范 + 可直接套用的工程模板。
>
> 本文档里的每一条硬约束、每一个坑，都来自一次真实交付：
> **《控制错觉》**（1920×1080 / 30fps / 123.500s / 无人声 / 已发布抖音）。
> 完整样例见 [`examples/control-illusion/`](examples/control-illusion/)。

---

## 0 一句话

**用「图形交互动画 + 事件拟声 + 氛围垫音」讲清一个反常识认知点。**
画面里的**图形是演员，文字是贴在演员身上的标签，声音只是动作的回声** ——
没有旁白，画面文字就是全部信息，所以每一句原稿都必须留在屏幕上。

**适用**：概率 / 心理学 / 底层逻辑类科普；有反常识认知点；能被图形化表达。
**不适用**：需要人声解说、实拍、剧情、访谈；纯口播；纯 PPT 录屏。

## 1 规格基线（先写死，后面不再重议）

| 项 | 基线值 |
| --- | --- |
| 画布 | **1920×1080（16:9）**，安全框 `0.05–0.95`（左右 96 / 上 54 / 下 1026 px） |
| 时长 | **120–150s**（本项目成片 123.500s = 3705 帧；未剪版 128.000s） |
| 帧率 | 30fps |
| 声音 | **无人声**：氛围垫音 + 事件拟声音效；关掉音效画面仍然叙事完整 |
| 交付 | HTML 源文件（单文件零依赖）＋ 逐帧渲染的 MP4 ＋ 音轨 WAV ＋ 封面 ＋ 发布文案 |
| 渲染 | 无头 Edge/Chrome 逐帧截图 → ffmpeg 合成；H.264 / yuv420p / tv 范围 / AAC-LC 44.1k 192k |
| 母版电平 | 整条音轨均匀 **+11dB** → 约 **−25.5 LUFS / 真峰 −0.5 dBTP** |

> 时长为什么是 120–150s 而不是 60s：无旁白片子的信息全部靠**阅读**获取。
> 实测阅读节奏是「每屏 1 个中心观点 + 其余文字降级成注释」，一条结论句需要 2.2s 以上的停留，
> 原稿 32 句压到 60s 会直接违反「不删句」的底线（见 §3.2）。

## 2 全链路八阶段

每阶段都有**可机器的验收**；只有两个节点需要停下来给人看：**第一镜样图**和**成片**。

| 阶段 | 产出 | 自证方式 |
| --- | --- | --- |
| ① 选题 & 文案 | 原稿（一字不改的句子清单） | `coverage.mjs` 逐句比对 |
| ② 分镜剧本 | 分幕网格 + 逐屏主角物品 + 节拍表 | 节拍表即唯一事实来源（画面/光影/音效同源） |
| ③ 视觉 & 动画 | 单文件 HTML（引擎 + 母题 + 附着层） | 几何体检：越界 / 重叠 / 碰撞 / 亮度 |
| ④ 音效 | 事件表 + 采样包 + 垫音 | `audio-render.mjs` 离线混音 + 电平 + `noise-floor.mjs` 噪检 |
| ⑤ 逐帧渲染 | 帧序列 | `render.mjs`（可分片并行） |
| ⑥ 合成导出 | 成片 MP4 | `ffprobe` 规格 + 静音版与带音效版**视频流 md5 相同** |
| ⑦ 裁剪 & 电平 | 上传主片 | 帧级内容扫描找低信息段；剪口相关系数 ≥0.99 |
| ⑧ 封面 & 发布 | 16:9 封面 + 正文/评论/标签 | 封面 8 条校验项量成品像素 |

**次序上的两条铁律**

1. **先出单屏原型并定稿，再铺满全片。** 本项目先做 S2 一屏（含引擎、附着层、音效、时序），
   过审后再把同一套组件推到 S3–S7；避免七屏做完才发现信息层级是错的。
2. **七屏全部过审后一次性整体渲染**，不渲染中间半成品。

## 3 选题 & 文案设计规范

### 3.1 选题筛选标准

四条同时成立才做：

1. **有一个反常识认知点**（「自己选号更容易中奖」这类直觉 vs 事实的落差）。
2. **能被图形表达**：核心机制可以用几何关系演示（等长刻度 = 概率相同；柱高比 = 4 倍）。
3. **有可引用的实证或机制**（经典实验、数据、认知机制），不是纯观点。
4. **结论对观众有用**（能带走一个判断工具），而不是只让人「哦」一声。

### 3.2 文案撰写规则（无旁白片子的底线）

| 规则 | 说明 |
| --- | --- |
| **完整保留原稿全部核心句子，一句不删** | 没有旁白时，被删掉的句子不是"留给观众想象"，而是永久丢失。本项目 **32 句 100% 在屏**，`A5` 锁定 |
| **每屏 1 个中心观点** | 其余文字**降级**为注释 / 标签 / 路径文字（尺寸、透明度、字体层级降级），不是删除 |
| **不删结论句** | 允许拆成 2 片相邻短注（拆开后 DOM 顺序拼回 = 原句，脚本按此校验） |
| **无旁白 ⇒ 文字是唯一阅读信息** | 任何一屏若出现「零文字零亮部」的空段，要么补注释要么剪掉（本项目剪掉了唯一一处 4.5s 空段） |
| **新增文字只能是非原稿的标注** | 如「主观：感觉更容易中奖 / 客观：中奖概率完全相同」这类对照标注，不得替换原稿句 |

### 3.3 时长与阅读节奏核算

- 正文下限 **52px**（1080p 基准），注释下限 **28px**；**不许靠缩字号塞内容**，靠"旧段落转暗"腾注意力。
- 单行出场 0.8–1.0s；**同屏行间隔 ≥2.2s**；段落之间额外 +1.2s。
- 屏尾留白（给观众读完最后一句）按屏长分档：**≥20s 的屏 ≥1.5s；≥8s 的屏 ≥1.0s；4s 钩子 ≥0.7s**。
- 台词量核算公式（本项目实测口径）：`Σ(每屏文字片数 × 2.2s + 段落间隔) + 换页 n×0.8s ≤ 总时长`。

### 3.4 叙事链（本仓库两部片子同构，直接照用）

**钩子 → 实证 → 命名 / 量化 → 迁移 → 机制 → 金句**，一步一环；屏数 7–8，
中间可以按题材多插一个「直觉 / 概念」环，但**不许跳环、不许调序**。

| 环 | 控制错觉（7 屏） | 幸存者偏差（8 幕） |
| --- | --- | --- |
| 钩子 | S1 金球「7」 | S1 线稿轰炸机 + 二选一提问 |
| （直觉 / 概念） | S2 圆环 + 球簇 | S2 机翼高光「加固机翼？」 |
| 实证 | S3 左右球阵列对照实验 | S3 四架小飞机中弹淡出 |
| 命名 / 量化 | S4 300px「4×」+ 对比柱 | S4 点阵 + 空缺 |
| 迁移 | S5 篮球 / 骰子 / K 线 | S5 空缺边界 + S6 三主场景 |
| 机制 | S6 大脑轮廓 + 4 光点 | S7 四光点依次脉动 |
| 金句 | S7 收尾金句 | S8 粒子汇聚 + 金句 |

两条硬规矩：**先现象后概念**（专业名词后置，不拿术语开场）；**结尾给一个可带走的判断工具**
（即 §3.1 第 4 条的交付物），不是「哦」一声。

## 4 分镜剧本设计规范

### 4.1 一镜一个核心概念 + 一个主角物品

**每屏先定义主角物品，物品先做动作，文字后到。** 这是全片观感的来源，
参照系是信息图而不是「黑底文案页」：

| 屏 | 主角物品 | 关键互动 | 文字怎么贴 |
| --- | --- | --- | --- |
| S1 钩子 | 金球「7」 | 轮廓生长 → 数字写入 → 漂浮 + 镜面虚影 + 微粒 | 三行楷体标签贴球侧（随球漂浮） |
| S2 概念 | 圆环 + 金球簇 + 灰球簇 | 圆环生长、环绕字自转、金球聚拢、灰球弥散、扫光横扫 | 标签贴簇顶；**长句拆成 4 条短注散在四角** |
| S3 对照实验 | 左右球阵列 + 中线 + 两个气泡 | 左组晃动 / 右组乱跳 → 中线自底向上拉伸 → VS → 气泡弹出 | 组标签贴阵列上；说明贴本组下方 |
| S4 量化数据 | 300px「4×」+ 8 球 vs 2 球 + 生长对比柱 | 柱从底部生长、小球一颗颗堆叠、数字随扫光登场 | 「足足高出四倍。」贴数字正下方（附着层） |
| S5 多场景 | 篮球 / 骰子 / K 线（依次登场） | 球弹起入网 → 骰子滚落 → K 线逐根生长 | 每栏标签 + 注释贴各自图形 |
| S6 机制 | 大脑轮廓 + 4 个光点 | 轮廓逐段描边 → 光点每 2s 依次脉动 | 4 个关键词各贴一个光点；右侧留白放注释 |
| S7 收尾 | 金句 + 四角粒子向心汇聚 | 粒子汇成水平线 → 金句金属登场 → 最后压暗 | 金句分两片居中；底部收束句 |

### 4.2 三类文字，权重绑定到物品

| 类 | 权重 | 形态 | 规则 |
| --- | --- | --- | --- |
| A 主标题 | 最高（但**低于图形**） | 金属渐变大字，每屏仅 1 个 | 不拆句；与主图形发生关系（压在环上 / 跟扫光出现） |
| B 附着标签 | 中 | 楷体小字 + 金色圆点，紧贴物品 | **与物品共用一条时间线**：位移/缩放/明暗逐帧跟随，距离用相对坐标固定 |
| C 补充注释 | 最低 | 衬线小字，透明度 .46–.62，可斜排/竖排 | 原长句**拆成多条短注分散**在图形周边，**禁止聚成一个大文本块** |

> 层级铁律：**图形 > 主标题 > 附着标签 > 边角注释**。

### 4.3 时序设计：图形先行

1. 主图形先登场（圆环生长 / 球阵列浮现 / 轮廓描边 / 大数字扫光）
2. 图形开始互动（金球聚拢 / 灰球弥散 / 对比线生长 / 光点脉动）
3. 标签跟随图形出现（图形高亮时标签淡入，相对距离恒定）
4. 补充注释**逐段**出现（不在同一时刻全部弹出）
5. 主标题最后锁定画面，触发全片最重音

硬指标：**最早图形动作 < 首句正文出现时刻**；同屏自主节拍最小间隔 ≥0.6s。

### 4.4 留白与冗余

- 全片最长连续空场 ≤0.6s；一屏内主动留出**低信息铺垫段**（本项目 S1 的 4.5–6.0s 全员静止，
  专门给观众读注释）——这段同时是后期裁切的**冗余缓冲**，剪短时优先动它。
- 钩子屏压到 4–6s；结尾屏留 3s 收束，最后 1–2s 只做呼吸不再出新元素。

### 4.5 系列结构约定（对标 7 部 Vibe 知识大赏，2026-10-09 实测）

原始数据、逐帧 OCR 与来源链接见 `参考/README.md`；本节只写结论。

| 约定 | 样片证据 | 本 skill 原先 |
| --- | --- | --- |
| **命名环节**：概念登场时给它一个名字，配一行英文副题 | 注意力缺失 / `SCATTERED ATTENTION`、遗憾的上限 / `THE UPPER BOUND OF REGRET`、运气的形状 / `DEFORM A FORTUNAE`、差一道题 / `ONE QUESTION APART`、房间里的按钮 / `THE BUTTON IN THE ROOM`（5/7 确认；05、06 未在 OCR 中读到） | 无（§4.1 只有「主角物品」） |
| **猜—答互动**：先让观众心里作答，再揭晓 | 复利篇全程 6 题（`第 N 题 / 共 6 题` + `Q1`–`Q6` 进度 + 「心里作答」）；37% 先立「规则一 / 规则二」再给答案 | 无（现有互动只有附着标签跟随图形） |
| **片尾三件套**：标题卡回归 → 一句互动提问 → 文献线索 | 07 `你上一次一个人发呆，是什么时候？` + `文献线索`；01 片尾同样是标题卡 + `文献线索` | 部分（§11 把互动提问只放评论区） |
| **示意 / 免责标注** | 07 `示意：这是帮你理解的模型，不是实验结果`、`请勿模仿`；06 常驻 `知识科普·不构成投资建议` | 无（§16 原先只讲素材授权） |

**没变的部分**（不必再论证）：7/7 无旁白（静音段 ≤2.8%、中频比低频低约 10dB）、暗底、
画面以静止为主（动帧占比 0.8%–5.5%）、金色克制（全片金色像素 ≤7.3%）。

## 5 视觉与动画设计规范

### 5.1 色彩（6 组 token，代码里不得再出现硬编码颜色）

| Token | 值 | 用途 |
| --- | --- | --- |
| `--bg-deep` | `#0A0A0A` | 背景基色（向深炭灰 `#141210` 渐变） |
| `--ink` | `#F5F1E8` | 暖白主文字 |
| `--ink-2` | `rgba(245,241,232,.62)` | 次级文字 / 正文 |
| `--ink-3` | `rgba(245,241,232,.30)` | 注释 / 顶部标识 |
| `--gold-hi` | `#D7B979` | 香槟金高光 |
| `--gold` | `#B8944A` | 暗金主色（描边 / 结构线） |
| `--gold-line` | `#8A7655` | 暗金灰：辅助线、刻度、概率曲线 |
| `--glow` | `#6B4A1A` | 棕金光晕（透明度 ≤ .09） |

层次至少四级：**深黑背景 → 暖白文字 → 香槟金关键词 → 暗金灰结构线**，再叠棕金光晕与少量金粒子。
只靠「黑 + 白 + 一个金色」就是「像加了个圆环的黑底页」。色值明细见 [`assets-guide.md`](assets-guide.md)。

### 5.2 四级文字层级

| 级别 | 角色 | 字号(1080p) | 行高 | 字重 | 用量限制 |
| --- | --- | --- | --- | --- | --- |
| L0 | 爆点（数字 / 关键词） | **160 / 300px** | 1.10 | 600 | 每屏 ≤1 处 |
| L1 | 大标题 / 金句 | 72–96px | 1.40 | 600 | 每屏 ≤1 处 |
| L2 | 强调句 | 60–64px | 1.55 | 500 | 每屏 ≤2 行 |
| L3 | 解释 / 注释 | 32–52px | 1.30–1.75 | 400 | 同屏 ≤3 行长句，其余拆短注 |
| L4 | 底部小字 | 28px，字距 .10em | 1.60 | 400 | 每屏 1 条 |

字体栈：正文衬线 `"Source Han Serif SC","Noto Serif SC","Songti SC","STSong","SimSun",serif`；
标签短句用楷体；**正文一律不用楷体**（可读性会崩）。

### 5.3 视觉母题（全片只用一套，不要每屏换装饰）

三件套：**彩票球 / 概率刻度 / 随机粒子**。同一母题在不同屏承担不同角色，这是「专题感」的来源。

| 母题 | 形态参数 | 用法 |
| --- | --- | --- |
| 彩票球 | 正圆 + 1.5px 描边 + 8% 同色径向填充；直径 90–240px；主球 220px，球内数字约球径 44%，**金色只给描边** | S1 氛围球 / S3 证据球阵 / S5 图标球 |
| 概率刻度 | 1px 主线 + 每 10% 一根 4px 短刻度 + 8px 游标点；语义「等长 = 概率相同」 | S2 单条 / S4 上下两条对照 |
| 随机粒子 | 60–80 个、直径 1–3px、两层视差、缓慢上浮、透明度 ≤0.15 | 全片常驻的「空气」 |

常驻的基础元素（全片统一，不得每屏更换）：**缓慢粒子 + 呼吸光晕**。
背景弱结构固定四件：极淡射线（14 条，0.25°/s）、低透明概率曲线、棕金光晕（呼吸 >30s）、四角暗角。

**禁止清单**：霓虹色、发光描边、玻璃拟态、科技感 HUD/网格、大色块渐变、弹跳回弹、打字机、
故障闪烁、粒子爆炸、位移 >40px 的转场、emoji 图标、真实照片、3D 渲染、
金色文字超过 5 处、同一屏两个同级视觉中心、每屏更换一套装饰元素。

### 5.4 动画规则

| 项 | 规则 |
| --- | --- |
| 单行出场 | 0.8–1.0s 内 `opacity 0→1` + `translateY 18px→0` + `blur 6px→0` |
| 入场后 | 极慢悬浮漂移（±6px，周期 14s），制造「悬浮」而非「贴纸」 |
| 旧段转暗 | 新段落出场后，之前的 L3 用 1s 降到 48%；**L0 爆点 / L1 大标题永远 100%** |
| 换页 | 旧屏 0.9s 淡出 + 新屏 0.8s 淡入，中间空场 ≤0.6s |
| 母题运动 | 平移 <12px/s、旋转 <5°/s、明暗周期 >5s |
| 呼吸 / 弹入 | 呼吸周期 **6.0s**、幅度 `0.90↔1.00`；弹入 `1.00→1.02→1.00`（0.9s）。**呼吸要慢，弹入要小**；全片呼吸 ≤3 处、弹入 ≤1 处，同一个词不做两种动效 |
| 禁止 | 位移 >40px 转场、弹性曲线、闪烁、任何「突然出现」、纯静态文字淡入（必须有图形交互） |

### 5.5 金属渐变字（金色关键词专用）

```css
background: linear-gradient(176deg,#FFF6DE 0%,#F4E1B2 20%,#EFDCAF 40%,#FFFBE9 58%,#EBD5A4 78%,#F6E7C0 100%);
-webkit-background-clip: text; background-clip: text; color: transparent;
-webkit-text-stroke: .6px rgba(74,48,12,.28);
filter: drop-shadow(0 8px 30px rgba(107,74,26,.42));   /* 绝不用 text-shadow（坑 7） */
```

- 第 58% 处必须有**比暖白更亮**的高光带 → 金属字必须是画面最亮处。
- 所有色阶灰度 ≥200，不允许出现暗金深色档（会把字压成「土金」）。
- 验收：关键词区亮度峰值 > 同屏任何白字，亮部(>140)占比 ≥15%。

### 5.6 版面约束

- 16:9 · 1920×1080；安全框 0.05–0.95（抖音 1080p：左右 96 / 上 54 / 下 1026）。
- **底部 10% 避开平台 UI 遮挡**：`y ≥ 0.80H` 的文字总宽 ≤0.35W，且不出现单条 >0.30W 的文本。
- 垂直方向「上重心」：内容块中心落在画布高度的 42%–48%。
- 每屏只有一个视觉中心（判据是字号或对比度上的**压倒性**）。
- 相邻两屏版式签名至少差 2 项（文字形态：竖排/斜排/标签/楷体/超大数字/大字群/环绕文字 ＋ 图形结构）。

## 6 音效设计规范

### 6.1 听觉架构

**氛围垫音（bed）+ 事件触发拟声（foley），无人声。**
音效只做「动作反馈 + 重点强调」，不讲故事。五条写死的原则：

1. 全程无旁白。
2. 音量压低：垫音 **−19.2dB**；拟声 **−22…−14dB**；爆点重音最高 **−12dB**。
3. 音效只在**动画事件触发点**播放，不循环、不铺满。
4. 同一时刻**最多 2 个**叠加（超出丢低优先级，重音 pri=3 优先）。
5. 关掉音效，画面叙事依然完整（音效是加分层）。

**硬性约束**：无长尾混响（点到即止）、音色统一偏暗金偏暖、杜绝尖锐高频与综艺特效音、
页面初始化即预加载全部素材（触发零延迟）。

### 6.2 工程实现

| 环节 | 做法 |
| --- | --- |
| 素材 | `audio/*.wav`：`soft_tick` / `swish_soft` / `low_impact` / `pulse_tap` / `sub_rise`（+`blank`）+ `ambient_pad.mp3` |
| 触发 | `SFX_EVENTS` 事件表，**时刻全部取自驱动画面的同一批常量**（节拍表）→ 音画同源、不漂移 |
| 调度 | 每帧把未来 0.3s 内的事件排队，按精确目标时刻调度；有 `AudioContext` 时走**采样级** `start(when)` |
| 并发 | 播放前统计仍在发声的实例，≥2 时丢弃低优先级；同类另有最小间隔（tick 0.18s / swish 0.35s / impact 1.5s） |
| 安全 | 跳转 / 回退 / 静态帧（`?t=`）一律不触发；`?sfx=0` 全程静音；缺素材静默降级、不告警 |

### 6.3 事件分配与重音配额

本项目未剪版全片 **30 条**事件：`swish_soft×8 / soft_tick×9 / pulse_tap×10 / low_impact×3`。
**重音严格三处**（绝不滥用）：

| # | 时刻 | 位置 | 音效 |
| --- | --- | --- | --- |
| ① | 16.6s | S2 金属标题「控制错觉」 | `low_impact` −12dB |
| ② | 51.7s | S4 金属大数字「4×」 | `low_impact` −12dB |
| ③ | 125.0s | S7 收尾金句 | `low_impact` −12dB |

分配原则：线条 / 轮廓生长 → `swish_soft`（−17…−20dB）；文字与标签淡入 → `soft_tick`（−21…−22dB）；
球体脉动 / 光点 / 小球堆叠 → `pulse_tap`（−21dB）；概念展开 → `sub_rise`；
**只有三处核心结论节点用重音**。

### 6.4 垫音合成规则（踩过大坑，逐条照做）

| 规则 | 原因 |
| --- | --- |
| **禁止混入宽带白噪 air 层** | `air = 0.995*air + 0.005*rand` 是 6dB/oct 漏积分，对 1kHz 以上只衰减约 −46dB → 整条垫音留下 **−43dBFS 的宽带嘶声** + 5–35Hz 次声摆动（「滋滋 + 嗯嗯」，全片贯穿，静音段也在） |
| 呼吸感由**振幅调制**产生，不是加噪声层 | 加噪声等于把刚清掉的嘶声用更贵的方式请回来 |
| 高通用 **二阶巴特沃斯 @20Hz（12dB/oct）** | 串联两次一阶 @30Hz 在 54Hz 处衰减 −2.33dB，会把低音根音削薄并压低整轨约 1.6 LU |
| 归一化与推子一起重算 | 去掉噪声层后「峰值归一到 −1dBFS」会整体抬高 1.17dB，推子最终写 **−19.2dB** 才等于原档 −18dB 的听感 |
| 剪辑拼接用**交叉淡化**，不能 fade to silence | 低频 BGM 直接淡到 0 会产生**听觉断点**（53.8Hz 长音断掉），这是坑 4 |

### 6.5 噪检判据（写死，不接受「听着还行」）

**① 先分清「文件自带」还是「本地监听」**：把导出文件拷到手机戴耳机听。
**高频嘶声手机能听见、低频嗡声手机听不见** —— 所以「手机听不到」**不等于**「是电脑接地干扰」。
只有**手机也没有嘶声**才算真干净。

**② 量测口径：汉宁窗逐帧频谱取帧间中位数；禁用「整段 FFT 高通后算 RMS」**
（40–80Hz 强音会向高频泄漏，能把 −132dBFS 的干净音轨量成 −72dBFS）。

| 量测项（帧中位） | 阈值 | 本项目修复后实测 |
| --- | --- | --- |
| 1–4kHz | ≤ −95 dBFS | **−121.4** |
| 4–8kHz | ≤ −100 dBFS | **−121.5** |
| 8–16kHz | ≤ −100 dBFS | **−121.5** |

**③ 定位顺序**（10 分钟）：单独播垫音 → 全轨 −6dB 预览（查叠加过载）→ 导纯音频 WAV 对比成品
（分离编码噪声）→ 换设备复听（分离本地监听）。

### 6.6 素材挑选要点

| 文件 | 检索词（英文优先） | 筛选标准 |
| --- | --- | --- |
| `soft_tick` | minimal glass tap / soft glass tick | 短、干净、**偏闷的玻璃轻触**，不要清脆叮咚铃音 |
| `swish_soft` | soft swish / minimal whoosh light | 慢、气流感，不是快速呼啸，无强风噪 |
| `low_impact` | minimal low impact short / soft stinger low thud | 低频扎实、衰减极快，不要爆破音、不要长混响 |
| `pulse_tap` | tonal pulse short / subtle resonant tap | 带一点柔和共鸣，像微小球体震动，不是电子哔声 |
| `sub_rise` | minimal rise fx slow | 平缓柔和爬升，不尖锐，不要惊悚悬疑感 |
| `ambient_pad` | minimal ambient underscore slow no drums | 无鼓点、暗调、长音垫；**无嘶声、无次声摆动**（选完跑 §6.5 量测） |

**避雷词**：epic / trailer / explosion / cartoon / ding / bell / sparkle / boom / loud / fantasy。
**实操**：波形尾部快速归零 → 叠上 bed 不抢戏 → 优先 44.1kHz 16bit 单声道 → 同类 2–3 个备选在原型里锁定。

> **拿到授权采样后同名覆盖即可**，事件挂载点 / 音量基线 / 并发限制都不用改。

## 7 HTML / CSS / JS 工程规范

### 7.1 结构：单文件、零依赖、可 seek

- 一个 `.html` 文件装下 CSS + JS + 全部画面；**无 CDN、无字体文件、无图片、无 emoji 图标**。
- 所有画面状态由 `t`（秒）计算：`render(t)` 是纯函数式渲染，
  支持 `?t=45` 精确定位任意一帧 —— 逐帧出片与截图体检都依赖这一点。
- 坐标系：`CANVAS = {w,h}`，位置走 `rx(r)=round(r*W)` / `ry(r)=round(r*H)`，
  字号与图形尺寸走 `rFont(px)=px*H/1080`。**切 2K 只改 CANVAS**（或 `?cw=2560&ch=1440`）。
- 起手模板：[`templates/shot-template.html`](templates/shot-template.html)（单文件、可跑、含调试参数）。

调试参数：`?t=45` 定位 / `?rate=0.5` 半速 / `?debug=1` 时间码 / `?sfx=0` 静音 / `?bgmvol=-19.2`。

### 7.2 P0 硬约束（七条，不可妥协）

| # | 约束 | 违反后果 |
| --- | --- | --- |
| ① | **禁止 `vw/vh/clamp()` 定字号与坐标** | 同一文件在 1280 与 1920 宽窗口里字号位置都不同，导出视频的版式不再是设计的那一版（坑 1） |
| ② | **`pieceIn` 与 `pop` 不能跑在同一个元素上** | 两个 keyframes 都写 `transform`，同属性只有最后一个生效，分片会「原地放大」丢掉上浮（坑 2） |
| ③ | **关键字动画不能用「自动播放」的 CSS animation** | `animation` 由插入时刻起算，无法被 `t` 定位，`?t=45` 拍到随机动画状态，出片必然错帧。要么全部由 `t` 计算，要么 `animation-play-state:paused` + 负 `animation-delay:-t s` |
| ④ | **字距 0.08em 会改变换行，必须逐片重测** | 大字用 0.04em、小字 0.08em；56px 正文原本一行约 15 字、加字距后约 14 字，会顶出右边界 |
| ⑤ | **`background-clip:text` 的元素禁用 `text-shadow`** | 阴影画在渐变之上，把金属字整体压暗约 45%，金色关键词比旁边的白字还暗，视觉重心反转（坑 7） |
| ⑥ | **文字落点必须取整像素** | 亚像素定位让字形发虚、金属渐变亮部被抹平，还显著增加视频码率（取整后亮部占比 2.1%→17%） |
| ⑦ | **循环型动画必须带时间常数断言** | 环绕文字转速多除了 60（1.8→0.05°/s）动画等于冻住，而几何与亮度体检都抓不到。组件内加阈值 `console.warn`，并把 warn 计入自检失败（坑 11） |

### 7.3 组件清单（用同一套，不要写第二套）

| 组件 | 职责 | 实现要点 |
| --- | --- | --- |
| `Item` 主角物品 | 每帧只更新四个量：微动位移 `dx/dy`、缩放 `k`、光照 `light`、在场权重 `on` | `ITEM_POS` 一份基准坐标被**三处共用**：图形本体 / 附着文字定位 / 光源关键帧 |
| `AttachmentLabel` 附着标签 | 位移=物品位移、缩放=物品缩放、与物品相对距离恒定 | `attachToLabel(item,text,{ox,oy,...})`；`ox/oy` 是相对物品中心的偏移（相对坐标，不写死像素） |
| `ScatteredNote` 散落注释 | 原长句拆成的短注释，各自独立 DOM、独立 start，散在图形周边 | 同句碎片在数据里必须**相邻**（`coverage.mjs` 按 DOM 顺序拼回原句） |
| `LightLink` 扫光联动 | 扫光扫到物品 → 贴在它身上的文字一起亮；物品沉入暗部 → 文字一起压暗 | `lf = (opMin + (opMax-opMin)·f(max(自身光照, 物品光照))) × 物品在场权重`，默认 `0.50↔1.00` |
| 母题构造器 | `lotteryBall(d) / probScale() / particles()` | 保证 S1/S3/S5 的球是「同一个东西」 |
| 图形件 | `ballRing / cloud / bubble / bar / hline / svgBox / brainDraw / converge / ballGrow` | 每个图形件登记 `start`，供「图形先行」验收 |

核心公式（照抄即可）：

```js
/* 附着层定位：物品中心 + 固定相对偏移 → 标签落点（相对坐标，切画幅不变形） */
function at(item, ox, oy) {
  var p = ITEM_POS[item];
  return { x: rx(p.x + (ox || 0)), y: ry(p.y + (oy || 0)) };
}
/* 扫光联动：文字明暗 = f(max(自身光照, 物品光照)) × 物品在场权重 */
var lf = (opMin + (opMax - opMin) * f(Math.max(pieceLight, itemLight))) * itemOn;
/* 每帧写 transform 时取整，避免亚像素发虚（P0 ⑥） */
el.style.transform = 'translate(' + Math.round(dx) + 'px,' + Math.round(dy) + 'px) scale(' + k + ')';
/* 循环动画的时间常数断言（P0 ⑦） */
if (spin < 0.3) console.warn('[orbit] 转速过低，检查时间常数');
/* 柱体绘制：top 必须减掉柱高（坑 9） */
el.style.top = (yBottom - h) + 'px'; el.style.height = h + 'px';
```

### 7.4 量测钩子（所有体检脚本都从这里取数，不要在脚本里写死画布）

```js
window.__seek(t)          /* 精确定位到 t 秒并静态渲染 */
window.__state()          /* {t, playing, total, w, h} */
window.__canvas()         /* {w, h, aspect, safe:{left,right,top,bottom}, ...} */
```

### 7.5 外部代码生成模型与替代管线（DeepSeek / Matplotlib / Manim / Remotion）

判断标准只有一条：**产物是不是一份可 seek 的单文件 HTML**。
是 → 谁来写都行；不是 → 它不在本 skill 的路径上。

**可以用的**：让任何模型（DeepSeek 之类）帮你写**这一份 HTML**。指令里直接带上 §7.1 与 §7.2 的
P0 ①–⑦ 原文让它照约束改，再按 §7.4 的量测钩子自检。这只是「谁来打字」的差别。

**不能用的一种做法**：把片子做成**逐帧文件**（`frame_0001.svg` / `frame_0001.png` …）再 ffmpeg 拼。
在本 skill 里它是净损失，理由不是审美：

| 会失去什么 | 为什么 |
| --- | --- |
| `?t=45` 精确 seek（P0 ③） | 帧序列只有序号、没有时刻；改一个字要重出全部帧 |
| A5 / A19 / A28 / A29 那批体检 | `coverage` / `narrative` / `attach-check` 全部经 `Runtime.evaluate` 读活 DOM 的 `.piece`、`window.__light()`、`window.__items()`（§7.4），帧序列上跑不了 |
| 音画同源 | 音效事件表引用节拍表常量；帧序列里画面时刻是文件序号，事件表对不上 |
| 零依赖（§7.1） | 每条替代管线都要再装一套环境 |

**替代管线不是本 skill 的实现**：Matplotlib / Manim / Remotion 的产物是 mp4 或帧序列，拿不到量测钩子。
真要用，只能当**上游素材生成器** —— 产出**一张图**或**一段独立 B-roll**，再喂进 HTML。
注意单文件片子不内联 `<img>`（§6.1），所以这条只对**封面**或**外挂 B-roll 片段**成立。

**想让模型直接出位图**：走 [assets-guide §8](assets-guide.md)（图片生成模型只做概念稿），
不要让文本模型把绘图 Prompt 转述一遍再拼帧。

三个照抄会出事的细节：示例里的 `ffmpeg -framerate 24` 在本 skill 是 **30fps**（§1），照抄会变速；
`cairosvg` / Manim 那类依赖本机没验证过，验证过的只有 **Node ≥18 + 无头 Chromium + ffmpeg**；
图片模型走 hypit 的 `gpt-image-2`（路由已用 `hypit plan` 验证通过）。

### 7.6 seek 安全补充（HyperFrames 独立佐证）

HyperFrames（同一套「HTML → 确定性视频」思路）把自己的硬约束写在
`upstream/hyperframes/skills/hyperframes-animation/rules-index.md` 的 contract 段。
与本 skill 的 P0 对照后，**重合的部分**（不用再论证）：只有一条**暂停的**时间轴、显式 from 状态、
状态必须是时间轴时间的纯函数、禁止自动播放的 CSS animation、禁止可变累加器。

它比 P0 ⑦ 多出来的三条，抄进来：

1. **随机与时钟**：`Math.random()` / `Date.now()` **不许参与画面状态**。粒子、抖动这类「随机感」
   只能**按元素索引导出**（`i` 的确定性函数）或初始化时抽一次种子固化进 `PIECES` ——
   否则同一个 `t` 两次渲染不是同一张图，A1/A19/A28 全部失效。
2. **群组错峰的总额**：同一批一起出场的元素，`个数 × 间隔 ≤ 约 0.5s` ——
   超过就把「一批到达」读成了「一串陆续到达」，一个节拍散成好几拍。
3. **动效只改 `transform` 与纯绘制属性**；`width/height/top/left` 不做补间（要用就换成
   `scaleY` / 遮罩）。本 skill 是每帧**直接写值**、不是补间，所以不受影响 ——
   但别因为「顺手」给动效元素挂上 CSS `transition`：它跑在浏览器时钟上，和 `t` 脱钩，seek 必闪。

## 8 渲染与导出规范

### 8.1 逐帧渲染 → 合成

```powershell
# 1) 逐帧截图（分片并行：每片只渲染 gi % shards == shard 的帧）
node render.mjs --html <html> --out <帧目录> --fps 30 --start 0 --end 128 --shards 3 --shard 0
# 2) 合成（必须做 full→limited 转换，否则手机播放黑位发灰）
ffmpeg -framerate 30 -i f%05d.jpg -c:v libx264 -preset medium -crf 18 -pix_fmt yuv420p -color_range tv out.mp4
# 3) 合音轨（视频流 copy，不重编码）
ffmpeg -i <画面.mp4> -i <bed.wav> -c:v copy -c:a aac -b:a 192k -ar 44100 out-sfx.mp4
```

### 8.2 导出参数（写死）

| 项 | 值 |
| --- | --- |
| 视频 | H.264 High / yuv420p / **tv 范围** / 30fps / 1920×1080 |
| 母版 | `-crf 18`（金属渐变、对比柱这类细节多的帧别用 crf 23） |
| 音频 | **AAC-LC 44.1kHz 192kbps** |
| 电平 | 整条音轨均匀 **+11dB** → −25.5 LUFS / 真峰 −0.5 dBTP（距平台 −14 LUFS 归一有充足余量，重音不触硬限幅） |

### 8.3 帧级画面校验（不靠肉眼）

| 检查 | 判据 |
| --- | --- |
| 空白段识别 | 逐帧统计**非背景像素占比 + 亮度分位**（p99.5）：亮部像素约 0.01%、p99.5 亮度 <45 = 低信息段 |
| 规格 | `ffprobe`：分辨率 / 帧数 / 时长 / pix_fmt / color_range |
| 视频流未改 | 同一画面源出的「静音版 / 带音效版 / 抬电平版」**elementary stream md5 相同** |
| 音频接缝 | 剪口 ±45ms 内样本跳变 ≤ 全片最大值的 1%（无咔哒） |
| 画面接缝 | 剪口 ±1 帧画面变化量落在全片常规区间内（无跳变） |

## 9 后期剪辑与成片导出（剪映专业版）

### 9.1 音轨分离与替换

1. 导入画面 MP4（静音版）→ 剪映「音频 → 分离音频」得到可操作音轨；
2. 换成正式授权素材时：删掉原音轨 → 拖入新音轨 → **首尾对齐到帧**（不要靠眼看波形）；
3. 事件音效与画面对齐的基准是**三处重音**（S2 标题 / S4 数字 / S7 金句），先对齐这三处再听中间。

### 9.2 音频交叉淡化（不能 fade to silence）

- 拼接 / 裁剪音频一律用**交叉淡化 60–150ms**，两段重叠区等功率交叉；
- **绝不允许**把 BGM 直接淡到 0 再起下一段 —— 低频长音会有听觉断点（坑 4）；
- 更稳的做法（本项目采用）：**垫音从文件 0 处连续取全长**，时间轴映射 `t<113.7` 不变、`t≥118.2` 前移 4.5s，
  事件按映射重新排布 → 53.8Hz 长音天然连续，不存在呼吸断点。

### 9.3 空白低信息片段的裁切

1. 先做**帧级内容扫描**（§8.3），把「零文字 + 零亮部」的段列出来；
2. 只在**低信息段内部**下刀，剪口两侧必须各留 ≥0.3s 有内容的画面；
3. 剪完验证：剪口处新版 `t` 与原版 `t+Δ` 的画面相关系数 **≥0.99**；
4. **不要在文字还在场上时下刀** —— 观众阅读注释的时间被删掉，比多留 4 秒更致命（坑 5）。

### 9.4 导出参数

H.264 / 30fps / 1920×1080 / **AAC 192k 44.1kHz**；
**不要把封面嵌进视频片头**（会改变视频时序、破坏音画对齐，坑 6）。封面单独出图上传。

## 10 封面设计规范

1. **16:9 · 1920×1080**，与成片同一套黑金低饱和质感。
2. **复用视频内已有的图形素材，不新增图形**：从成片静帧抽背景板、从数据屏抽对比柱、
   用正片同一份 `.metal` 材质现渲数字。（图片生成模型只能做概念稿，见 [assets-guide.md](assets-guide.md) §8）
3. **优先突出数字钩子**：缩略图里第一视觉应该是那个反常识的数字（本项目 `4×`，
   字号 430px = 主标题的 2.6 倍），标题第二重要。
4. **缩略图可读性优先**：去掉图形内部细碎刻度，**加粗轮廓**（外轮廓 2.4px / 2.0px 抗糊加固）。
   本项目因此在两个候选里选了「极简柱」而不是「带刻度柱」。
5. **底部 10% 留空**：抖音播放器 UI 会压上来，主体墨迹最低点必须在其上方
   （本项目柱底 y=932，核心区下沿 972）。
6. 出图：JPG q90 成品 + PNG 无损母版；另出 `540×304` 与 `540×960` 两张缩略测试图做可读性校验。

## 12 避坑总表

### 12.1 六条定型坑（每一条都是真事故）

| 坑 | 现象 | 根因 | 修法 |
| --- | --- | --- | --- |
| **坑 1** `vw/clamp` 版式错乱 | 同一文件在不同浏览器窗口里字号、位置都不同，导出视频与设计稿不一致 | `font-size:clamp(28px,5vw,88px)`、`--x:-42vw` 依赖窗口宽度 | 一律写 1080p 画布坐标的绝对 px；字号走 `rFont()`（P0 ①） |
| **坑 2** transform 同属性动画覆盖 | 分片「原地放大」，丢掉上浮位移 | `pieceIn` 与 `pop` 都写 `transform`，同属性只有最后一个生效 | **外层元素做位移入场，内层元素做缩放**，各管一个 transform（P0 ②） |
| **坑 3** make-foley 的 air 白噪层 | 全片贯穿「滋滋 + 嗯嗯」底噪，静音留白段也在；手机同样能听见 | `air = 0.995*air + 0.005*rand` 是 6dB/oct 漏积分，1kHz 以上只衰减 −46dB | 删掉 air 两行；呼吸感改由 `breath` 振幅调制；加二阶巴特沃斯 20Hz 高通。1–4kHz 从 −77.3 → **−121.4dBFS** |
| **坑 4** 剪辑里低频 BGM fade to silence | 剪口处明显听觉断点（低频长音断掉） | 把 BGM 直接淡到 0 再起下一段 | 交叉淡化 60–150ms，或让垫音**从文件 0 处连续取全长**、只重排事件（§9.2） |
| **坑 5** 过早裁切画面 | 观众还没读完注释就被剪走 | 只看了「没有大图形」就下刀 | 帧级内容扫描 + 剪口两侧各留 ≥0.3s 有内容画面 + 剪口相关系数 ≥0.99 |
| **坑 6** 把封面嵌进视频片头 | 视频时序被改变，音画对齐整体错位 | 片头加 1–2s 封面图 | 封面单独出图上传；成片第 0 帧就是钩子屏 |

### 12.2 项目实测补充的十条（同样会致命）

| # | 坑 | 现象 / 根因 | 修法 |
| --- | --- | --- | --- |
| 7 | `background-clip:text` + `text-shadow` | 金属字被压暗约 45%，金色关键词比旁边白字还暗 | 用 `filter:drop-shadow()`；需要边缘暗部用 `-webkit-text-stroke` |
| 8 | 环绕文字容器缺 `position` | `.ringtext` 的逐字 span 相对 `#structures` 左上角定位，**从早期版本起一直渲染在画外**；旧脚本只查透明度没查位置 | 容器补 `position:absolute`；体检必须**同时查位置和透明度** |
| 9 | 柱体绘制忘记减柱高 | `bar(x,yBottom,w,h)` 把 `top` 设成柱底 → 475px 高的金柱 88% 落在画外，成片里两根柱看起来一样高，4 倍差距没表达出来 | `top = yBottom - h`；图形件要有「几何自证」——封面按本意几何出图后反而暴露了正片这个 bug |
| 10 | 分片 `nowrap` / 字距改变换行 | `nowrap` 分片超过可用宽度直接顶出安全区；加 0.08em 字距后原本一行的句子变两行、相邻分片互相压住 | 大字 0.04em / 小字 0.08em；宽度贴近上限的分片显式 `nowrap` 并逐片复测；改换行要按「行高×行数」重算纵向排布 |
| 11 | 环绕文字转速时间常数写错 | 转速多除了 60（1.8→0.05°/s），动画等于冻住，几何与亮度体检都抓不到 | 循环组件内加阈值断言 `if (spin < 0.3) console.warn(...)`，warn 计入失败条件 |
| 12 | 整段 FFT 量噪声底 | 40–80Hz 强音向高频泄漏，把 −132dBFS 的干净音轨量成 −72dBFS | 用**汉宁窗逐帧**（186ms 帧 / 50% 重叠）取帧间中位数 |
| 13 | `ffmpeg` stereo→mono 的 3.01dB 尺子差 | s16 与 f32 输出差 3.01dB（同源 mp3：s16 −14.86 / f32 −11.85）；走 s16 路径却拿 f32 解码去量，会把 −18dB 量成 −21dB，误判成工程差来回改推子 | 量之前先确认解码位深；相减残差掉到 −101dB（完全抵消）就是「尺子差」的特征 |
| 14 | 去噪后归一化抬高电平 | 去掉 air 层后「峰值归一到 −1dBFS」整体抬高 1.17dB，推子还写 −18dB 就会比原档响 | 归一化与推子一起重算；本项目最终推子 **−19.2dB**（根音与原档差 ≤0.25dB） |
| 15 | 滤波选型削薄低音 | 串联两次一阶 @30Hz 在 54Hz 处衰减 −2.33dB，根音被削薄、整轨压低约 1.6 LU | 用**二阶巴特沃斯 @20Hz**（54Hz 处仅 −0.08dB） |
| 16 | 无头浏览器 canvas 画中文回退成方框 | DOM 渲染正常、canvas `fillText` 出缺字方框，导致「行盒→墨迹中心」补偿算错 | 封面/图表的墨迹补偿**从成品图实测标定**，不用 canvas 估算 |

### 12.3 两条流程性教训

- **不要推翻已定稿的骨架去做「全局优化」。** 外部优化方案里 6 处「替换原稿句」最终没做：
  那些「旧文案」在成片里并不存在，而原稿 32 句是 `A5` 锁死的骨架。要动就是下一个版本
  （连字数、停留时长、换行一起重排），不是这一版的补丁。
- **先发出去看真实反馈，再针对性改那一句**，比凭预判全量重写更准。

### 19.2 动效信条里可以照抄的四句

1. **平滑压倒回弹** —— 长尾减速是默认，回弹是「明确玩闹」的罕见例外。
   （本 skill §5.4 已禁弹性曲线，方向一致。）
2. **顺序揭示放在后段，不要在前 25% 倒完** —— 这是「像 PPT」与「像片子」的分界。
   本 skill 没有旁白，所以对位的不是语音，而是**节拍表**：§4.3 已经要求
   「主图形先登场 → 注释逐段出现 → 主标题最后锁定」，把「后 50%」当成量化口径用它。
3. **宁可不给动效，也不给坏动效** —— 后半段的缓慢平移 / 推近会打乱视线，是负收益；
   静止的一帧胜过被「呼吸」撑活的一帧。
4. **内部的接缝要速度匹配** —— 不是静止叠化，而是切在速度峰值上、两侧同向同速。

### 19.3 两处冲突，明确怎么处理

| 冲突 | 他们的做法 | 本 skill 怎么办 |
| --- | --- | --- |
| **变速剪辑的位移量** | cut-the-curve 用 ±230px 的位移做场景接缝 | **不采纳整条** —— 撞 §4.6「位移 >40px 的转场」禁止。只取两个可用细节：① **模糊量随主体尺寸**（文字类 10px、整屏面 18–20px，且切点两侧数值必须相同）；② **淡出在行程的 25–30% 处就完成**，不等到出画 |

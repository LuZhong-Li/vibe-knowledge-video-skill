# 旁白工作流（分支 A 带旁白 / 分支 C 共用）

> 对应 README §27.4。流水线本体是 `tools/narration.mjs`（TTS → 时长拟合 → 排布 → 与 foley/BGM 混音），
> 本文件把它正式化：什么时候用、怎么用、判据怎么放宽。

## 1 什么时候用旁白

| 情形 | 建议 |
| --- | --- |
| 无旁白动画科普（Vibe 风格） | 保持无旁白；A5「原稿 100% 在屏」必过 |
| 内容文字密度大、口播能省一半阅读负担 | 带旁白（画面留关键词，旁白说全句） |
| 用户点名要解说 / 配音 | 带旁白 |
| 分支 C 的口播 / 录屏素材 | 人声已存在，直接用；`narration.mjs` 只用于补 TTS 占位或旁白轨对齐 |

**核心规则：旁白稿 = 画面文字母本。** 旁白每句台词都要能在画面上找到对应文字（或同一时刻的关键词），
不允许"旁白说的和画面写的各说各话"——这是带旁白片子最典型的扣分点。

## 2 工作流（五步）

1. **旁白稿**：逐句成文（每句 ≤ 一句话），每句标注归属画面分片（出场时刻从分片取，保证音画同源）。
2. **生成与拟合**：
   ```bash
   node narration.mjs --html <成片.html> --voice "Microsoft Huihui Desktop" --out <输出目录>
   ```
   TTS 逐句生成 → 按分片出场时刻排布 → 输出音轨 + 脚本 + SRT。
   Windows 本地 TTS 音色是占位音色；正式发布前换成真人录音（第 4 步）。
3. **混音**：`--bed <foley+bgm.wav>` 压音混音（人声压在垫音上，事件音效躲开人声密集段）。
   导出前：`noise-floor.mjs` 噪检、整轨电平到 §6 口径（真峰 ≤ −0.5 dBTP）。
4. **真人录音替换**：把 TTS 音轨换成同长录音（按「旁白脚本-时间码」压），**画面不用重渲**。
5. **字幕**：旁白脚本即字幕稿（SRT/ASS）；验证每屏字幕阅读时长（复用 §23 的"字幕逐条在屏"思路）。

## 3 带旁白时哪些判据放宽（对照 §27.4）

| 判据 | 无旁白（A 默认） | 带旁白 |
| --- | --- | --- |
| A5 原稿 100% 在屏（`coverage.mjs`） | **必过** | 不再是必过项；屏幕文字可只留关键词，中心观点句仍在屏 |
| 文字可读性下限（§5.8） | 硬线 | **仍是硬线**（旁白不豁免画面文字可读性） |
| 音效事件表（§6.3） | 重音全片 3 处 | 重音配额不变，但人声段落内事件音效要降级让位 |
| 文字阅读节奏（§3.3） | 2.2s/句 | 可放宽到 1.2–1.6s/句（信息由耳朵承担一半） |

## 4 硬约束

1. 旁白与画面文字**同源**（同一条分片表），不许另写一套。
2. 人声不许削波（真峰 ≤ −0.5 dBTP）；压音用限幅，不要整体压低垫音。
3. 事件音效躲开人声密集段（§6.3 的并发上限照算，人声算一条"长素材"：≥900ms 独占一拍）。
4. 字幕在安全框内（横屏底边 ≤ 90%H / 竖屏 ≤ 92%H），读速中位 5–8 字/秒。
5. 真人录音替换时保留时间码表，画面不需要重渲；**改过画面必须重新对旁白时间码**（对齐失效比没对齐更糟）。
6. TTS 音色仅作占位——发布前必须确认音色可用或换真人，别把合成音当成品交。
